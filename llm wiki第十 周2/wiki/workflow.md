# 可追溯考前測驗 Agent：Graph / Loop 規格

## 範圍

本流程是教學設計，不是已上線的測驗工具。它示範如何為每門課建立隔離的專案，從上傳講義／簡報或公開連結整理重點與產生有依據的選擇題，再用作答結果維護錯題集。

## Graph 主線

```text
開始
  → 建立／選擇課程專案
  → 管理專案（命名、上傳檔案／公開連結、範圍、題庫、錯題庫）
  → 來源可讀取？
      ├─ 否 → 明確提示權限／格式錯誤 → 請換連結或上傳檔案
      └─ 是 → 繼續
  → 選擇模式與本次範圍
  → 讀取來源並建立證據卡
  → 覆蓋率與來源關卡
      ├─ 證據不足 → 標示缺口／請使用者補資料 → 停止該範圍出題
      └─ 足夠 → 產生選擇題
  → 題目驗證
      ├─ 不通過 → 只修正該題 → 再驗證（最多 2 次）
      ├─ 仍不通過 → 排除並記錄，不放入正式題庫
      └─ 通過 → 加入專案題庫
  → 使用者選回饋模式
  → 逐題作答與批改
      ├─ 答對 → 下一題
      └─ 答錯 → 顯示補強依據 → 使用者選「重練」或「跳過」
             ├─ 重練 → 針對同一證據概念出新題 → 回到作答
             └─ 跳過 → 寫入該專案本機錯題庫 → 下一題
  → 成績、範圍覆蓋與錯題報告
  → 下載考前重點 PDF／題目集 PDF／錯題集 PDF
  → 完成
```

## 兩種資料模式

### 講義模式

- 只檢索本課程專案的使用者上傳檔案與可讀取連結。
- 每題和解說附講義來源及位置。
- 無證據時標示「資料未提及」，不以一般知識補答案。
- 遇到登入牆、權限不足或格式問題時明確回報並要求替代輸入。

### 深入模式

- 先使用課程資料證據，再由使用者允許的網路搜尋補充。
- 外部來源只用學術、官方或可信專業資料。
- 網路補充採醒目琥珀色標籤，附標題、作者／機構、日期（若可得）與連結。
- 不把外部解釋偽裝成課程講義內容。

## 課程專案狀態

每個專案至少保存：

```text
project_id
course_name
materials[] # 上傳檔案或可讀取的公開連結
default_scope
question_bank[]
wrong_question_bank[]
mode_preferences
```

使用者可新增、選擇、命名與刪除專案。專案範圍預設包含全部課程資料；使用者可儲存考試範圍，也可在單次測驗調整。跳過的錯題保存在該課程的本機錯題集；考前重點、題目集與錯題集均可下載 PDF。

## Loop 的界線

- **生成 Loop：**每題個別通過來源、正解與選項檢查；最多修正兩次，仍不合格就排除並報告。
- **學習 Loop：**答錯後由使用者選擇重練或跳過；可隨時結束，跳過題回到之後錯題練習。
- 不因單題錯誤重跑全部來源擷取或重建整份題庫。

## 人工關卡與檢查

| 關卡 | 人工決定／程式檢查 |
|---|---|
| 專案設定 | 使用者選課程、講義、模式與考試範圍 |
| 證據覆蓋 | 檢查範圍有沒有來源；不足時請補資料 |
| 題目驗證 | 唯一最佳答案、來源支持、模式標籤、選項格式 |
| 作答回饋 | 使用者選即時回饋或最後統一批改 |
| 錯題分流 | 使用者選重練或跳過 |
| 匯出前 | 檢查檔案所屬專案與題目／錯題數量 |

## 為什麼用 Graph 加 Loop？

Graph 先固定跨課程專案、模式、題目檢查與錯題分流的路徑；Loop 只在出題修正和錯題練習的小範圍內反覆執行。這可讓錯誤在離來源最近的關卡被抓到，也讓人知道錯誤會回到哪一步。
